# Потік монет

Адаптивний лендинг із симулятором заощаджень і доступними формами з валідацією.
Стек: **HTML5 + Tailwind CSS v4 + Vanilla JavaScript** (без фреймворків і бібліотек).

## Можливості

- **Симулятор заощаджень**: дохід, витрати, відсоток, періодичність, строк. Складний відсоток із щомісячною капіталізацією, графік, збереження сценарію в `localStorage`, кнопка «Поділитись».
- **Три форми** з клієнтською валідацією: відгук, реєстрація, розсилка.
- **Відгуки**: нові відгуки з'являються на сторінці одразу (зберігаються лише в браузері).
- **Доступність**: семантична розмітка, `label`/`for`, `aria-*`, повна навігація з клавіатури, модальне вікно на нативному `<dialog>`.
- **Адаптивність**: mobile-first, меню-бургер до 1280 px, таблиця порівняння з горизонтальним прокручуванням.

## Структура проєкту

```
.
├── index.html          # сторінка
├── js/
│   ├── main.js         # меню, симулятор, відгуки
│   └── validation.js   # валідація форм і модальне вікно успіху
├── styles/
│   ├── style.css       # вихідник Tailwind (токени, компоненти)
│   └── output.css      # зібраний CSS (генерується)
└── assets/             # logo.svg, hero.svg, icons/
```

## Запуск

Потрібен [Node.js](https://nodejs.org/) лише для збирання CSS.

```bash
# одноразова збірка
npx @tailwindcss/cli -i styles/style.css -o styles/output.css --minify

# режим розробки (перезбирає при змінах)
npx @tailwindcss/cli -i styles/style.css -o styles/output.css --watch
```

Після збирання відкрийте `index.html` у браузері або запустіть локальний сервер:

```bash
npx serve .
```

## Валідація форм

Помилки показуються лише після взаємодії з полем (blur / input / submit). Стани полів: **normal → focus → error → success**.

| Поле | Правило |
|---|---|
| Ім'я | не порожнє, щонайменше 2 символи |
| Email | коректний формат (`name@example.com`) |
| Телефон | необов'язковий; якщо вказано, строго `+380XXXXXXXXX` |
| Повідомлення / відгук | щонайменше 10 символів |
| Згода | чекбокс має бути відмічений |

Регулярні вирази:

```js
const PHONE_REGEX = /^\+380\d{9}$/;
const EMAIL_REGEX = /^[^\s@]+@[^\s@.]+(\.[^\s@.]+)*\.[^\s@.]{2,}$/;
```

Для невалідного значення функції `explain…Error` підказують, що саме не так (немає `@`, зайві цифри, пробіли в номері тощо).

## Відправка на сервер

За замовчуванням відправку **вимкнено**: після успішної валідації відкривається модальне вікно з приміткою, що сервер не підключено.

Щоб підключити бекенд:

1. У `js/validation.js` змініть `SEND_TO_SERVER = false` на `true`.
2. У `index.html` замініть `action` форм (`/api/review`, `/api/signup`, `/api/newsletter`) на реальні адреси.
3. **Повторно перевіряйте всі поля на сервері.** Клієнтська валідація не є захистом.

Додатково: у формах є приховане поле-пастка `contact_pref` (honeypot) від ботів, а відгуки виводяться через `textContent` (без `innerHTML`).

## Доступність

- Кожне поле має `<label for>`; помилки зв'язані через `aria-describedby`, поля позначаються `aria-invalid`.
- Помилки озвучуються через `aria-live="polite"`, підсумок форми через `role="status"`.
- Клавіатура: `Tab`/`Shift+Tab`, `Space` для чекбокса, `Enter` для відправки, `Esc` закриває модальне вікно, стрілки/`Home`/`End` перемикають вкладки симулятора.
- Фокус у модальному вікні утримується, після закриття повертається на попередній елемент.
